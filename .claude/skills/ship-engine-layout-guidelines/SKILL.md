# Skill：舰船引擎布局规范（1 主 + 2 辅引擎簇）

## 目标

- ASTD 舰船的引擎在视觉上**统一为“1 主喷口 + 2 辅喷口”的引擎簇**，形成有主次层次的尾焰，而不是一排等大的单喷口。
- 主辅同色同样式，靠**尺寸**拉开层次（主大辅小），保证 mod 内引擎观感一致。
- 改造已有舰船时**不破坏原有美术对齐**：主喷口沿用现有引擎槽的位置与朝向，辅喷口在其两侧对称派生。

## 适用范围

- `contents/data/hulls/*.ship` 的 `engineSlots`。
- 新建舰船、或为现有舰船配好 bloom/发光美术后统一引擎观感时。
- 引擎尾焰样式（颜色/拖尾）见 [[engine-styles]]（`contents/data/config/engine_styles.json` 内的 `ASTD_ARC` / `ASTD_LENS` 等），本规范只约定**布局**，不约定颜色。

## 核心约定（强制）

### 1) 引擎簇 = 1 主 + 2 辅

每个“引擎单元”由 3 个槽组成：

```
        辅(+)
主         ← 喷射方向（由 angle 决定）
        辅(-)
```

- **主喷口**：决定该单元的位置、朝向、尾焰主体。
- **2 个辅喷口**：在主喷口两侧、**沿垂直于喷射方向**对称分布，做出“主亮辅细”的层次。

### 2) 主口宽度统一，长度保留

- **同一系列舰船的主喷口 `width` 统一为一个常数**，避免同船/同系列出现宽窄不一、个别喷口过宽过亮。
  - ASTD 基准：主口 `width = 10`（与 `astd_gravitational_lens` 主口一致，全 mod 引擎粗细统一）。
- **`length` 不统一**，保留各喷口原有长度（体现喷口主次/大小布局）。
- 统一宽度时**只收窄超宽的，不拉宽窄的**：`width = min(原width, 10)`。小船原本就细的喷口保持原样，不被强行加粗。

### 3) 辅口尺寸 = 主口 55%

- 辅喷口取主喷口的约 **55%**：
  - `width = round(主width * 0.55)`（主口统一 10 → 辅口 `6`）。
  - `length = round(主length * 0.55)`（随各主口长度变化）。
  - `contrailSize = round(主contrailSize * 0.55)`。
- 向最近整数取整；`width` / `length` 至少为 `1`。

参考实现（lens 舰）：主 `len35/w10` → 辅 `len20/w5`。

### 4) 偏移方向与距离（固定间距）

辅喷口相对主喷口，沿**垂直于喷射方向**的法线 `±offset` 平移：

- 喷射方向单位向量来自主喷口 `angle`：`dir = (cos(angle), sin(angle))`。
- 法线 `normal = (-sin(angle), cos(angle))`。
- 辅口坐标：`location ± normal * offset`。
- **`offset` 为固定常数（ASTD 基准 `4`px），与主口尺寸无关。** 所有辅口间距一致，引擎簇紧凑统一。
- 辅口的 `angle` 与主口**完全一致**（同向喷射）。

> ⚠️ `offset` 必须固定，**不要**按主口 `width` 缩放。曾用 `offset = width*0.9`，导致宽主口的辅口被推得很远、整船引擎显得散乱。固定间距才能让所有簇看起来一致。
>
> 为什么是垂直法线而不是固定 ±Y：舰船有斜喷引擎（`angle≠180`），固定按 Y 轴偏移会让斜喷的辅口错位。按法线偏移对任意朝向都正确。

### 5) 样式归属

- 主、辅喷口**共用同一 `style`**（如 `ASTD_ARC`）。不为辅口单独建样式——层次靠尺寸，不靠颜色。
- 同一**系列**的所有舰船共用同一引擎尾焰样式（例如 ARC 系列全部用 `ASTD_ARC`），与 hull 命名是否带 `arc_` 前缀无关——以世界观系列归属为准。
- 例外：若某舰确实需要“主亮辅暗”的颜色对比，才新增 `*_SUB` 样式；默认不这么做。

## 改造流程（对现有舰船）

1. **确认对象**：通常是“已配好 bloom/发光美术”的舰船（`builtInWeapons` 含 `*_bloom` / `*_lights`，且 `graphics/ships/` 有对应 bloom 图）。先把这些船统一到本规范。
2. **把现有每个引擎槽视为主喷口**，原样保留其 `location` / `angle` / `length`；`width` 按 §2 收窄到统一值；`style` 改为该系列的尾焰样式。
3. **为每个主喷口派生 2 个辅口**，按 §3 §4 计算尺寸与坐标，`style` 与 `angle` 沿用主口。
4. **最小化改动**：用脚本就地插入辅口，保持 `.ship` 原有缩进与单行数组格式，避免整文件重排造成噪声 diff。改完用严格 JSON 解析校验。
5. **不动根级 `style`**（hull style）与 `bounds`；只动 `engineSlots`。

## 校验清单

- [ ] 每个原引擎槽现在对应 1 主 + 2 辅，共 ×3。
- [ ] 辅口 `angle` 与对应主口一致；辅口在主口两侧对称（法线方向）。
- [ ] 辅口尺寸 ≈ 主口 55%，`width≥1`。
- [ ] 主辅 `style` 一致。
- [ ] `.ship` 仍是合法 JSON；git diff 仅为新增辅口槽，无格式污染。

## 反面案例

- ✗ 辅口按固定 ±Y 偏移 → 斜喷引擎的辅口会跑偏。用法线偏移。
- ✗ 用 `json.dump` 重写整个 `.ship` → 单行数组被拆多行，产生数百行噪声 diff。用就地字符串/结构化最小插入。
- ✗ 给辅口单独配更花的颜色 → 破坏 mod 引擎观感统一。层次用尺寸。
