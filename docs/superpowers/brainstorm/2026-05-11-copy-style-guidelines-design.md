# 文案风格硬约束 SKILL 设计文档

> 状态：已批准，待规划
> 日期：2026-05-11

## 概述

创建一份 SKILL.md（`.agents/skills/copy-style-guidelines/SKILL.md`）和一个文案审查 Agent（`.agents/agents/copy-review.agent.md`），为 Asteria Directorate 模组的所有玩家可见文本建立硬约束文案标准。

覆盖范围：全部玩家可见文本（对话、赏金文案、船体/武器/系统描述、hullmod 描述、状态文本、赏金词缀）。

目标：风格统一、质量门槛、写作效率，三者同时解决。

---

## Layer 1 — 通用硬规则（所有文本强制执行）

每条规则配 1 个"好的示例"（优先从现有文案提取）+ 1 个"违规示例"（构造的反例）。

### R1: 叙事化而非说明书化

文本负责营造"用起来什么感觉"，数值交给 UI 层（tooltip / stat card）。

- ✅ "超载离子束聚焦器，以更高的能量消耗换取毁灭性的穿透力。"
- ❌ "伤害+20%，射程+15%，辐能产出+10%。"

### R2: 短句 + 强动词，禁止套话开头

每句 ≤25 词。首句直接进入主题，禁止"这是一种/该武器/此舰船/被设计用于/在战斗中扮演"等套话。

- ✅ "烧穿相位线圈，将敌舰拖入现实空间。"
- ❌ "这是一种能够使相位舰船强制退出相位状态的武器。"

### R3: 世界观内部视角，不跳出第四面墙

文本从世界观内部说话，用该宇宙的角色会用的词汇。

- ✅ "弧光回路在过载阈值之上依然保持凝聚——代价是核心寿命。"
- ❌ "该技能设计用于高风险高回报的战斗场景。"

### R4: 数值归 UI，文案归感觉

所有数值由 `{%s}` 占位符或 UI 层承载。文案零裸露数字。

- ✅ "光束 DPS 动态 = 最大辐能容量 × {%s}。"
- ❌ "光束 DPS = 最大辐能 × 15%，每秒耗辐能 500。"

### R5: 代码零硬编码

所有玩家可见文本必须从 strings.json / CSV i18n 键读取。引用已有 `localization-guidelines` SKILL 的完整规范。

### R6: 术语一致性（双线词库对齐）

动词、形容词、意象必须对齐文本所属路线。见附录 A 双线词库。

### R7: 留白原则

信息密度 ≤70%。留下 30% 让玩家脑补——不说尽。

- ✅ "沉默的卫兵在守护什么？一段无人记得的指令，还是某个更深层的遗产。"
- ❌ "这些无人机被设定于 3214 年执行防御协议 7-Alpha，至今仍在运行。"

### R8: 反"不是…而是…"句式

禁止以否定副词（不是X、并非Y、而非Z）引导或收束正向断言的任何句式。包括："不是A，而是B"、"不是A，不是B，而是C"、"X，而不是Y"。直接陈述正向断言，删除否定半句。

- ✅ "它在局部时空连续体上撕开裂口。"
- ❌ "这不是简单的能量释放，而是对时空结构的强制重写。"

### R9: 反公式化语法

禁止的句式模式：

- "在…中/下" 开头长状语 → 拆成主动句
- "通过…来实现…" 叠床架屋 → 直接用动词
- "一种…的…" 套娃修饰 → 限 2 层
- "值得注意的是/值得一提的是/综上所述" 等过渡套话 → 删除
- "当…时" 延迟主语 → 主语前置
- 堆砌"而/且/并/同时" → 一句话只保留一个连接关系

- ✅ "弧光回路锁定目标。耀斑注入完成。"
- ❌ "在弧光回路锁定目标的情况下，通过向核心注入耀斑能量来实现瞬间的伤害输出，且同时触发护盾过载。"

### R10: 情感锚点唯一

每段文本有且仅有一个核心情感。不混杂。

### R11: 角色声音一致（对话类专属）

每个说话者的措辞、句子长度、隐喻池必须一致。守望者说长句、留白；回声说碎片化短句；审判者说判断性短句。

## Layer 2 — 分类专项模板

### 2.1 武器描述

```
结构：一句定调 → 机制叙事（1-2句，感官语言）→ 引语（可选，引号包裹的 lore 碎片）
动词必须对齐武器所属路线（弧光/透镜词库）。

示例结构：
「[定调句，10-15词]。[机制叙事，用感官语言描述效果]。」
「"[一句世界内引语]"」
```

### 2.2 船体描述

```
结构：出身/背景 → 设计意图 → 战术角色（3句封顶）
每句必须传递一个可感知的事实或画面。
```

### 2.3 舰船系统描述（descriptions.csv）

```
结构：技术叙事（2-3句，用该系统的"声音"）→ 代价/后果（1句）
载人/自律双模式：必须写出两种模式的不同"人格"。
禁止：列出属性、堆砌百分比。
```

### 2.4 系统状态文本（systems_strings.json）

```
格式已有硬规范（system-status-text-guidelines）：台词风格，IN/ACTIVE/OUT 三阶段，多模式独立键。
新增约束：每阶段的状态文本必须形成一个"弧线"（起→承→合）。
```

### 2.5 Hullmod 描述

```
短描述（1句，12词内）：意象化命名句。
长描述（2句）：设定 → 战术效果（感官语言）。
赏金词缀：必须同时满足"可感知的战术变化"+"世界内合理性"。
```

### 2.6 对话（strings.json / Dialog DSL）

```
角色声音优先：措辞、句子长度、隐喻池一致。
禁止：信息倾泻（一段塞入 3+ 个事实点）。
禁止：功能性对话（"我需要你去做X"），改为动机化对话。
```

### 2.7 赏金任务文案（docs/story/）

```
保持现有三段式：悬念勾引 → 技术情报 → 哲思收束。
新增约束：每段的"时间层次"必须清晰（即时/中层/深层至少出现一层）。
```

## Layer 3 — 审查检查清单

AI 执行用，每项 Yes/No。

| # | 检查项 | 适用类型 |
|---|--------|----------|
| R1 | 文本是在讲故事还是在报参数？ | 全部 |
| R2 | 每句 ≤25 词？首句跳过了套话？ | 全部 |
| R3 | 是否存在第四面墙词汇？（玩家、平衡、机制、buff、debuff、触发、判定…） | 全部 |
| R4 | 数值全部由 `{%s}` 占位或 UI 层承载，文案零裸露数字？ | 全部 |
| R5 | 所有可见文本是否从 I18n 键读取，代码无硬编码？ | 全部 |
| R6 | 动词/形容词是否对齐所属路线？（弧光 vs 透镜词库） | 武器/系统/船体描述 |
| R7 | 信息密度 ≤70%？是否留下玩家脑补空间？ | 全部 |
| R8 | 是否存在"不是…而是…"等否定式对比结构？ | 全部 |
| R9 | 是否存在公式化语法？（"在…下"、"通过…实现"、"当…时"…） | 全部 |
| R10 | 角色声音一致？ | 对话类 |
| R11 | 情感锚点是否唯一且清晰？ | 全部 |
| R12 | 状态文本是否形成弧线？（IN→ACTIVE→OUT 起承合） | 系统状态文本 |

**违规项处理：**

- 1-2 项 → 标注并建议改写，作者修正后重新审查
- 3+ 项 → 退回重写，不可合并

## Layer 3.5 — 强制审查流程

新增/修改任何玩家可见文本后，强制执行：

1. 调用文案审查 Agent（`@copy-review`）
2. 审查输出格式：

```
┌─────────────────────────────────────┐
│ 审查文件：<path>                     │
│ 审查时间：<timestamp>                │
│                                      │
│ R1  ☑ pass / ☒ fail — <原文摘录>    │
│ R2  ☑ pass / ☒ fail — <原文摘录>    │
│ ...                                  │
│ R12 ☑ pass / ☒ fail — <原文摘录>    │
│                                      │
│ 违规项改写建议：                     │
│  R8 fail — "不是简单的能量释放，而是…"│
│  → 改："它在局部时空连续体上撕开裂口。"│
│                                      │
│ 结论：☑ 全部通过 / ☒ N项违规        │
└─────────────────────────────────────┘
```

3. 违规项修正后重新审查，直到全部 pass
4. 审查报告写入 `.agents/superpower/copy-review/<YYYY-MM-DD>-<file-ref>.md`

## 文案审查 Agent 配置

```
文件：.agents/agents/copy-review.agent.md

职责：只读审查玩家可见文本，不修改文件
触发：用户显式调用，或 SKILL 内强制要求

输入：变更的文本文件路径 / diff / 直接粘贴的待审文本
输出：逐条对照 Layer 1 规则（R1-R12）的 pass/fail 列表

配置：
  - agent 类型：只读审查
  - 必须加载：.agents/skills/copy-style-guidelines/SKILL.md（审查标准）
  - 审查范围识别：自动识别输入文本属于 Layer 2 的哪个分类，
    只对该分类适用的规则做判定
```

## 附录 A — 双线词库

### 弧光计划（蓝）

- 动词：释放、贯穿、撕裂、点燃、轰击、倾泻、过载、饱和
- 形容词：锐利、炽烈、瞬时、不可阻挡、纯攻击
- 意象：闪电、铸炉、锋刃、烈阳、洪流、燃烧
- 代价词：烧蚀、熔毁、过载、崩解

### 透镜协议（紫）

- 动词：扭曲、渗透、解构、回响、折射、层叠、衰减、共振
- 形容词：深邃、缓慢、无处不在、递归、非线性
- 意象：深渊、迷雾、潮汐、回音、枝蔓、镜廊
- 代价词：坍缩、蚀刻、衰减、失稳

### 中立/通用

- 动词：维持、导向、校准、耦合、闭锁、逐退
- 名词：回路、中继、栅格、拓扑、统御意志、相位、辐能

## 附录 B — 禁忌词表（硬禁止，触碰即违规）

### 元游戏用语

玩家、平衡、机制、buff、debuff、触发判定、游戏内、本模组

### 套话开头

这是一种、该武器、此舰船、被设计用于、在战斗中扮演

### 公式化句式标记

在…中/下、通过…来实现、一种…的…、当…时、值得注意的是、值得一提的是、综上所述

### 否定对比结构

不是…而是…、并非…而是…、X，而不是Y

### 属性堆砌裸词

伤害、射速、装甲、护盾、辐能（作为裸名词列出的情况；叙事语境中如"护盾矩阵"可接受）
