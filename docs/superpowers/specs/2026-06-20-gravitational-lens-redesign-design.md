> 日期：2026-06-20

> 状态：设计稿（待用户调整 / 简化意见）。

## 0. 核心设定（已锁定，不可更改）

| 项 | 设定 |
|---|---|
| 定位 | **半航母半巡洋** |
| 主要防御 | **重盾 + 高级电子战能力** |
| 飞行甲板数 | **4** |
| 武器槽 | **1 大型导弹 + 2 中型协同 + 2 中型能量 + 4 小型能量** |

### 0.1 战斗节奏定位（设计取向）

**镀点控场型指挥舰**。生存依赖重盾与电子战，缓慢推进；核心价值是
**「未出场先压制」**——通过电战 / 透镜机制成片削弱敌军，使全队获得输出窗口。
甲板、协同武器、能量武器是辅助输出，而非主体。

### 0.2 紫线主题约束

- **哲学**：信息优势 + 空间操控 + 认知信息战（视点即真相）。
- **动词**：扭曲、渗透、解构、回响、定影。
- **意象**：深渊、迷雾、潮汐、回音、残影。
- **文案**：技术-诗意黄金配比，避免夸张 / 中二 / 否定句式（见 STYLE_GUIDE）。

## 1. 设计总览（最终选案）

| 类别 | 选案 | 支柱 / 定位 |
|---|---|---|
| 舰船系统（选 1） | **D 回声定影（Echo Fixation）** | 延迟结算的区域威慑 |
| 内置插件 · 基座（必带） | **① 透镜阵列核心（Lens Array Core）** | 全局指挥 / 双模式中枢 |
| 内置插件 · 选案 | **③ 视差甲板（Parallax Decks）** | 4 甲板支柱 |
| 内置插件 · 选案 | **④ 渗透潮汐（Permeating Tide）** | 高级电战支柱 |

> 选择过程中被否决的方案（不实现）：系统 A 折射假象、系统 C 静默宣讲、
> 系统 B 潮汐透镜（早期剔除）、插件 ② 深蓝视界护盾、插件旧 ④ 失焦装甲。
> 记录于此仅为避免后续重复发散。

### 1.1 统一咬合约束：标记闭环（Mark Loop）

本舰所有机制围绕一套**「标记 → 全队增伤」闭环**协同，避免各机制各自为政：

```
铺点（系统 / 机群） → 沉淀（插件标记） → 收割（核心·载人模式 战术链路 全队增伤）
```

- **误差标记（Drift Mark）**：通用增伤标记。由系统 D、插件 ③ 机群命中铺设，可叠加。
- **深水标记（Deep Water Mark）**：电战压制标记。由插件 ④ 高潮位铺设，可与误差标记叠加，
  并对系统 D 的护盾削弱有叠乘关系。
- **收割**：插件 ①（载人模式·战术链路）令全队对**任意被标记目标**伤害 +10%。

> 所有系统 / 插件的展开中，凡涉及「标记」均指同一套闭环，由统一的标记数据结构承载
> （实现层：建议一个 `LensMarkState`（接口 + Impl），挂在目标 ship 的 customData 上，
> 记录标记类型、层数、剩余时间；由各机制读写，由核心收割时统一查询）。

## 2. 舰船系统：回声定影（Echo Fixation）

*"我把这一刻拓下来。它会替你们，再死一次。"*

**定位**：延迟结算的区域威慑。逼迫场内敌舰移动（打乱输出 / 阵型），或承受站桩惩罚。
是「时间信息战」而非「引力物理场」，专属于控场指挥舰的缓慢节奏。

### 2.1 机制（定影 → 回放 两阶段）

- **定影阶段（4s）**：在鼠标指定区域（半径 ~700su）生成「观测快照场」。
  场持续记录场内每艘敌舰的位置 / 状态。
- **回放阶段（场结束瞬间）**：每个被记录敌舰的「过去坐标」浮现残影；
  对**残影半径内的当前敌舰**施加「认知撕裂」效果，持续 ~4s：
  - 护盾效率骤降；
  - 承受伤害提升。
  - 原理叙事：其「现在」与本舰记录的「过去」对不上，相变重构（紫线·幻觉剥离）被干扰。
- **越站桩越痛**：站着不动的敌舰（过去 ≈ 现在）残影与本体重合，效果最强；
  走位躲开的敌舰效果线性衰减 —— 奖励本方逼敌走位、惩罚敌方贪输出。

### 2.2 与插件咬合

- 被「认知撕裂」命中的敌舰叠 **1 层误差标记**（接入标记闭环）。
- 若目标已带 **深水标记**（插件 ④ 潮汐），认知撕裂的护盾削弱**额外加深**
  （电战压制与时间信息战叠乘）。

### 2.3 数值锚点（v0，待平衡）

| 参数 | 值 |
|---|---|
| 冷却 | ~14s |
| 场半径 | ~700su |
| 定影时长 | 4s |
| 残影命中半径 | 待定（建议 ~150su / 敌舰） |
| 认知撕裂时长 | 4s |
| 站桩判定 | 重合 = 满效，偏移按距离线性衰减至 0 |
| 误差标记 | 命中即叠 1 层 |

### 2.4 落地路径与风险

- **记录**：每帧（或定影期间按固定间隔）遍历 `engine.ships`，存场内敌舰位置历史快照。
  已有遍历框架（`ASTDProjectileVfxRuntimePlugin` 的扫描式插件范式）。
- **回放 debuff**：临时 HullMod + `AffixCausalityLagHullMod` / `AffixRecordedLoopHullMod`
  （名称即「因果延迟 / 记录回放」）思路复用。
- **残影 VFX**：BoxUtil / sprite 叠绘敌舰残影。
- **风险**：
  - 需存敌舰位置历史快照（每帧存 loc）——内存 / 性能可控，但**必须设场内目标数与历史长度上限**，
    超限要 `log()` 丢弃，避免静默截断。
  - 站桩 / 偏移的衰减阈值需实测调参。

## 3. 内置插件 ①（基座）：透镜阵列核心（Lens Array Core）

*"真相只是一个可调节的变量，而我握着旋钮。"*

> 承载本舰的**双模式切换逻辑**（无人 / 载人），是 `00-common.md` §5 要求的主干插件。
> 紫线特化的纳米重构 = 装甲优先（幻觉剥离）。
> **必带基座，不参与选择。**

### 3.1 双模式

- **[无人模式] 全域拓扑态**
  - **蜂群思维**：本舰所有机群 +速度、+射程（4 甲板特化）。
  - **幽灵信号**：周围 ~2000su 内敌舰制导精度下降（被动电战光环）。
- **[载人模式] 宏观锚定态**
  - **情报中枢**：为**全舰队**提供 ECM 等级加成（指挥舰本职）。
  - **战术链路（标记闭环·收割端）**：全队对**任意被标记目标**（误差 / 深水）伤害 +10%。

### 3.2 共性

- **纳米重构协议**：紫线特化（装甲修复优先）。见 `ASTDNanoRestorationProtocolHullMod`。
- **敌方难度缩放**：作为 Boss / 敌对单位时，数值按 `m ∈ [1.0, 1.5]` 受难度系数放大
  （仅敌对单位，呼应 `BountyScalingHullMod`）。

### 3.3 落地路径与风险

- 双模式切换 ← `ASTDArcFlareDualModeSwitcherHullMod` 现成范式直接复用。
- 纳米重构 ← `ASTDNanoRestorationProtocolHullMod`。
- 全队增伤收割 ← 遍历友军 + 查询目标标记状态（统一标记数据结构）。
- **风险**：低。范式齐备。需确认「全队对被标记目标 +10%」的实现走 on-hit 增伤修饰
  而非全局 buff，以正确限定「仅对被标记目标」。

## 4. 内置插件 ③（选案）：视差甲板（Parallax Decks）

*"它们从你看不到的角度出现。"*

> 强化「4 甲板」支柱。机群不是普通舰载机，而是带电战 / 空间操控属性的信息战机群——
> 但本舰仍是控场指挥，机群是「铺标记的载具」而非主体输出。

### 4.1 机制

- **错位部署**：本舰机群发射时带短暂「相位错位」——刚出库的机群有 ~2s
  隐形 / 无敌窗口（降低甲板被压制时的机群损耗，呼应紫线「切频道」相位味）。
- **链路回响（标记闭环·铺点端）**：本舰机群对敌人造成伤害时，
  为该敌人叠 **1 层误差标记**（与系统 D 同源、可叠加）。机群成为全场铺标记的工具。
- **回收重构**：返航机群进入护盾范围时，加速补充 / 修复（紫线装甲优先重构的延伸）。

### 4.2 数值锚点（v0，待平衡）

| 参数 | 值 |
|---|---|
| 出库隐形 / 无敌窗口 | ~2s |
| 机群 on-hit 叠标记 | 1 层（建议设每秒叠加上限，防刷） |
| 返航回收加速 | 待定 |

### 4.3 落地路径与风险

- 发射隐形窗口 ← 改 fighter phase / collision（出库瞬间设短时无敌 / 不可选中）。
- on-hit 叠标记 ← `onHitEffect`，范式 `ASTDPursuitVirtualParticleOnHitEffect`。
- 返航回收 ← 监测 fighter 与本舰距离 / 是否在护盾范围。
- **风险**：
  - 中等。「出库隐形窗口」对 fighter 的相位 / 碰撞 API 支持度需验证。
  - 机群 on-hit 叠标记需设**每目标每秒叠加上限**，否则 4 甲板高频命中会瞬间堆满标记。

## 5. 内置插件 ④（选案）：渗透潮汐（Permeating Tide）

*"它不是一堵墙，是一片正在涨起来的水。等你发觉时，你的信号已经在水面以下了。"*

> 钉死「高级电战」支柱。把电战从①的被动 ECM 光环，升级为一个**会涨落、随交战时长加深的
> 渗透式压制场**。主题用 `00-common.md` 命名库中列出但尚未使用的「潮汐（Tide）」。

### 5.1 机制（三段）

- **涨潮（Rising Tide）—— 压制随时间加深**：
  本舰持续在场，周围 ~2500su 形成「电战潮汐场」。压制强度**随本舰在场时间缓慢累积**，
  作用于场内敌舰：制导精度下降、武器射程小幅缩水、ECM 贡献被侵蚀。
  打持久战潮位越高 —— 契合「未出场先压制 + 缓慢推进」。
- **退潮反制（Ebb）—— 给敌方清晰破局面**：
  当本舰**护盾过载 / 受大量集火**时，潮汐退去，压制强度临时大幅下降并需重新涨起。
  给敌方明确反制窗口（集火打断电战），符合「留反制面」。
- **深水标记（Deep Water）—— 接入标记闭环**：
  高潮位时，场内停留过久的敌舰被打上 **深水标记**（与误差标记同源、可叠加），
  离场后短时残留。再次把电战压制接进全队增伤闭环。

### 5.2 与系统 / 其他插件的张力

- 与系统 D 咬合：深水标记令 D 的护盾削弱叠乘。
- 设计张力（备注）：本插件「越挨打越弱」（退潮），与早期被否决的 ②深蓝视界护盾
  「越挨打越强」形成对冲——②已不入选，此处仅记录设计意图来源。

### 5.3 数值锚点（v0，待平衡）

| 参数 | 值 |
|---|---|
| 潮汐场半径 | ~2500su |
| 涨潮速率 / 上限 | 待定（持续在场缓慢累积至上限） |
| 退潮触发 | 护盾过载 / 短时受到大量伤害 |
| 退潮幅度 / 恢复 | 临时大幅下降，需重新涨起 |
| 深水标记 | 高潮位 + 场内停留过久触发 |
| 敌方难度缩放 | 潮汐上限与涨速按 `m ∈ [1.0,1.5]` |

### 5.4 落地路径与风险

- 潮位状态机（涨 / 退）← `AdvanceableListener` 每帧维护。
- 范围 debuff ← `AffixJammingNodesHullMod` / `AffixVectorSilenceHullMod`（「矢量沉默」电战味）。
- 退潮触发 ← `fluxTracker.isOverloaded` / 短时受伤累积。
- 深水标记 ← 统一标记数据结构。
- **风险**：低。状态机 + 范围 debuff 范式齐备。需确认「ECM 贡献侵蚀」对原版 ECM 系统的
  作用方式（按敌舰 ECM 贡献降百分比，参考 v0 的 ECM 归零压制思路）。
