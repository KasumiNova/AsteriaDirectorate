# 第一章细化：积压工单

> 定稿日期：2026-09-04。上位文档：`02-赏金主线构思.md`；前章：`03-序章-新来的承包商.md`。
> 赏金条目全文案：`06-第一章赏金条目文案.md`。
> 本章职责：确立"接单 → 出击 → 核销 → 读档案"的章节循环，把词缀系统与难度爬坡正式引入，
> 并用档案室第一层铺完全部世界观底色——总局的日常、两院分工、与速子科技的竞争。
> 基调：官僚机构的体温还在。

## 章节结构：三批工单

本章赏金以**批次制**发放：每批若干单同时挂出，玩家可自由顺序完成；
同批全部核销后，系统"结清批次"并挂出下一批。批次之间无时间限制。

### 批次一「例行核销」（2 单）

- 内容为普通高威胁目标（海盗头目/违约资产），**不挂词缀**；
- 舰队规模：预设 **120 FP**（按 02 文档 FP 全局算法缩放）；
- 功能：让玩家熟悉工单终端操作与核销流程；
- 文书口吻：例行公事，备注栏甚至有格式化的敷衍——
  "本单属常规积压件，无特殊条款。"

### 批次二「条款追加」（3 单）

- **词缀系统自此介入**：目标开始携带词缀，首批 1 个，本批末单 2 个；
- **舰队规模自此增强**：预设 **200 FP**；开始出现**少量主力舰**（约占 15% FP）；
- 叙事化表达：核销交割后，系统回执上多出一条批注——

> 「系统提示：目标威胁评估已于你方出击期间更新。相关条款已按章程追加至后续工单。
> 由此产生的风险增量，已计入报酬调整。特此告知。」

- 这是词缀系统在剧情上的"开门"：玩家第一次意识到**这家机构的情报是活的**。

### 批次三「加急件」（1 单）

- 本章高潮单：词缀组合 + 舰队规模上调，目标为一份**加急文书**
  （编号带"加急"戳记——两百年前的加急）；
- **赏金势力固定为「余晖」**；舰队规模预设 **300 FP**；
- 完成后承包商等级提升：**一级 → 二级**；
- 加急件的冷幽默：备注栏写着"请优先处理"，签发日期是两个世纪以前。

## 报酬

- 单票星币报酬区间：**300,000 ~ 1,500,000**，随模组难度系数缩放（规则同 02 文档）；
- 每批结清时发放**批次结清奖金**：批次一 **300,000** / 批次二 **500,000** /
  批次三 **750,000**，均随难度系数缩放、**最高 5×**；
- 每单明细单照旧：条款、批注、金额逐项列示——报酬叙事是本章"体温感"的主要来源。

## 档案室：第一层

阅读解锁：随核销进度逐份开放（建议节奏：批次一解锁 1~2 份，批次二解锁 3~5 份，
批次三后全开）。第一层共 7 份档案，定标题与内容概要如下：

| # | 档案 | 内容概要 |
|---|---|---|
| 1 | 《总局组织章程（节选）》 | 设立宗旨：签发、裁决、记录。全篇没有一个"统治""复兴"字眼。 |
| 2 | 《星坠理事会与紫菀理事会分工备忘录》 | "星坠造矛，紫菀磨镜"的公文版：两院同源同址、业务分明、互不隶属、互相验收。 |
| 3 | 《与速子科技竞合关系年度通报（第 187 期）》 | 两院与速子竞标同一批人之领订单；措辞克制，火药味从标点里渗出来。 |
| 4 | 《分局资产年检报告（连续第 203 期）》 | 一切正常。**连续两百年，一切正常。**——年检至今仍在自动运行。 |
| 5 | 《外勤协调员管理条例》 | 代办的行为规范原文：着装、欠身角度、话术规程。玩家会认出序章里的每一个细节。 |
| 6 | 《战斗群保障条例（存目）》 | 只有目录，没有正文。目录条目编号不连续。全文依保密条令不予展示。 |
| 7 | 《承包商管理办法》 | 玩家权利义务：乙方义务 47 条，甲方义务 3 条。第 47 条是"本办法解释权归甲方所有"。 |

叙事功能：#1~#3 铺世界观（两院分工 + 速子竞争）；#4~#5 立"体温感"与代办谜底回收；
#6 埋编号战斗群伏笔；#7 是玩家身份的公文确认。

## 章末钩子

批次三结清后，工单终端弹出两份新类目，名称异常朴素：

> 「系统提示：检测到封存工单类目申请解锁。
> 类目：【星坠理事会 · 武器试验场遗留工单】
> 类目：【紫菀理事会 · 科研遗址遗留工单】
> 解锁条件已满足。——需要说明的是，这两份类目不在本分局常规清算序列之内。」

同时，已结清的工单列表里，某一份的状态栏短暂显示过一次：
**「目标状态：现役？」**——随后自行恢复为"已核销"。系统不做任何解释。

（→ 第二章「两份章程」双线入口；状态栏异常为中点转折「核销」的远伏笔。）

## 机制对接清单

| 机制 | 本章内的用法 |
|---|---|
| 批次制工单 | 每批同时挂出、自由顺序、整批结清后解锁下批；无时限 |
| 舰队规模 | 统一以**舰队点数（FP，ship_data.csv 原生量）**为口径，缩放走 02 文档 FP 全局算法（难度系数 × 玩家超模系数 ≤2× × 舰队大小系数）；预设值：序章 80 / 批次一 120 / 批次二 200 / 批次三 300 |
| 词缀系统 | 批次二起介入：1 → 2 → 组合；条款批注作为系统级叙事口径，后续章节沿用 |
| 难度系数 | 词缀数值与组合数量、舰队规模按系数缩放；报酬同步缩放 |
| 星币报酬 | 单票 300,000 ~ 1,500,000；批次结清奖金 30万/50万/75万，缩放最高 5× |
| 模组总 UI | 空间站对话新增选项作为**模组总 UI 入口**；交互与特效另开专项设计文档 |
| 承包商等级 | 一级 → 二级（本章唯一一次升级），等级决定后续章节工单可见范围 |
| 档案室 | 阅读解锁制；7 份档案随核销进度逐份开放，纯阅读无战斗 |
| 伏笔系统 | 「目标状态：现役？」一次性闪现；不向玩家解释、不可查询；**不考虑防读档** |

## 基调守则（本章专用）

- 本章是"循环章节"，叙事密度靠**档案与回执**承载，战斗本身不带剧情对话；
- 所有系统提示保持公文语体；惊悚点（状态栏闪现）用界面事故的方式呈现，不用演出呈现；
- 报酬明细单、批次结清回执是"机构还活着"的体感来源，文案待遇与主线文书同级。

## 模组总 UI 入口（新增决策，2026-09-04）

- 玩家与分局空间站交互后，对话选项中出现**模组总 UI 入口**（工单/档案/账户等模块的统一入口）；

  （「目标状态：现役？」一次性格式化闪现即由该 UI 承载，**不考虑防读档**）；
