# 赏金系统机制（主线/支线/词缀/动态生成）

本文件描述阿斯忒里亚遗构局"扩容版"赏金线的系统机制架构，旨在通过技术手段承载深层叙事内容。

> **设计哲学**：主要难度来自机制创新与词缀组合，数值提升只做支撑性调整。

---

## 系统核心理念

### 叙事驱动的机制设计
- **每个系统都服务于世界观**：词缀超越了简单的数值修改器，它是阿斯忒里亚技术遗产的实质具现化。
- **渐进式复杂度**：随着玩家深入剧情，解锁的不仅是更强的敌人，更是更深层的哲学冲突
- **选择的重量**：机制设计确保玩家的决策对后续剧情产生真实影响

### 双线对立在系统层的体现
- **弧光计划词缀**：强调瞬间爆发与正面对抗（超频线圈、零余量纪律）
- **透镜协议词缀**：强调空间控制与信息战（干扰节点、相位不稳定）

## 核心系统架构

### 主线赏金（Milestone Bounties）
- **总量扩容**：从原版 12 个节点扩展至 24 个，实现更细腻的剧情节奏
- **叙事锁定**：每个主线赏金都包含不可替代的剧情片段，确保体验连贯性
- **解锁机制**：完成主线 N 解锁主线 N+1，同时开放对应的支线内容池

### 动态支线生成（Procedural Side Content）
- **故事碎片投放**：随机生成的赏金任务中嵌入阿斯忒里亚历史档案
- **奖励多样化**：
  - 本模组特色武器（`astd_` 前缀优先级）
  - 稀有制品与 AI 核心
  - 隐藏的技术数据与设计图纸

### 词缀系统（Affix Framework）
> *"每一道词缀，都是阿斯忒里亚设计师们留下的技术印记。"*

词缀作为具有深度背景设定的技术遗产，远超简单的属性修改器：

#### 弧光计划词缀（ARC Protocol Affixes）
- **超频线圈** `astd_affix_overclocked_coils`：电容过载，爆发伤害提升但散热压力增加
- **零余量纪律** `astd_affix_zero_margin`：极限操作模式，性能提升但容错率降低
- **电弧共振** `astd_affix_arc_resonance`：能量武器威力增幅，但产生连锁反应风险

#### 透镜协议词缀（LENS Protocol Affixes）
- **干扰节点** `astd_affix_jamming_nodes`：电子战干扰，降低敌方锁定与武器精度
- **相位不稳定** `astd_affix_phase_instability`：空间扭曲效应，随机位移与护盾闪烁
- **引力透镜** `astd_affix_gravity_lens`：空间弯曲武器，穿透掩体但能耗巨大

#### 通用技术词缀（Universal Tech Affixes）
- **熵化护盾** `astd_affix_entropy_shields`：护盾反馈机制，受击时对攻击者造成伤害
- **超压推进** `astd_affix_reckless_drive`：引擎超频，机动性提升但结构应力增加

## 动态缩放算法

### 双系数平衡模型
```
难度系数 (D) ∈ [1, 3]     // 基础任务难度
超模系数 (P) ∈ [1, 5]     // 玩家舰队实力评估
总系数 (T) = min(15, D × P) // 上限 1500%

归一化难度 k = clamp([0,1], (T-1)/14)
```

### 舰队规模计算
```
目标 FP = 基准 FP × T
实际强度 = 基础数值 × (1 + k×0.08) × 词缀加成
```

### 组成比例分配
- **50%** 阿斯忒里亚舰船（`astd_*_Standard` 变体优先）
- **40%** 星区常见舰船（排除模组特色，保持世界观一致性）
- **10%** Omega/残党舰船（高端威胁，营造神秘感）

## 进度门控与解锁机制

### 词缀池演化
```
序章完成     → 解锁基础词缀（1-2 个/任务）
第一幕 25%   → 解锁进阶词缀（2-3 个/任务）
第二幕 50%   → 解锁高阶词缀（3-4 个/任务）
第三幕 75%   → 解锁终极词缀（4-5 个/任务）
全线完成     → 解锁传说词缀（自由组合）
```

### 叙事联动机制
- **选择记忆**：玩家在关键节点的决策影响后续词缀类型
- **技术路线锁定**：偏向弧光计划的玩家面对更多透镜协议敌人，反之亦然
- **道德评判**：「审判者」AI 根据玩家行为调整最终挑战的难度与性质

## 技术实现架构

### 代码组织结构
```
MagicBountyBridge: 赏金生成与注册接口
├── 主线赏金: 硬编码保证剧情完整性
├── 支线生成: 动态刷新保证重复可玩性
└── 词缀系统: 模块化设计支持热插拔

BountyCampaignManager: 战役层面的状态管理
├── 进度跟踪: 记录玩家选择与解锁状态
├── 舰队缩放: 实时计算难度与奖励
└── 叙事联动: 根据进度调整后续内容

AffixFramework: 词缀的统一管理框架
├── 词缀池管理: 按进度动态解锁
├── 强度计算: 基于归一化系数的平滑缩放
└── 效果实现: HullMod形式的模块化效果
```

### 平衡性监控
- **数据埋点**：记录玩家完成时间、失败次数、舰队损失
- **动态调节**：根据统计数据调整词缀强度与出现概率
- **A/B测试**：为不同类型玩家提供差异化的挑战曲线

### 模组兼容性
- **软依赖检测**：自动识别其他模组的舰船与武器
- **平衡性适配**：根据环境强度自动调整基准难度
- **冲突规避**：避免与主流模组的核心机制产生冲突

## 设计验证标准

### 叙事一致性检查
- 每个机制都能在世界观中找到合理解释
- 词缀名称与效果符合对应技术路线的哲学内核
- 难度曲线与情绪曲线保持同步

### 可玩性评估
- 新手玩家能在序章感受到模组特色
- 资深玩家在终章仍能感到挑战
- 支线内容提供足够的探索动机

### 技术可维护性
- 模块化设计支持快速迭代
- 清晰的接口定义便于后续扩展
- 完善的错误处理避免游戏崩溃
