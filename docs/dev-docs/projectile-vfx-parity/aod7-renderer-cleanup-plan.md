# AOD-7 Projectile VFX Renderer Cleanup Plan

> Required for implementation: use TDD. TS preview layout and renderer code are the source of truth. Do not tune Kotlin runtime constants from screenshots.

**Goal:** Make the game runtime render from the same AOD-7 projectile VFX layout contract as the TS preview, while removing hidden scale factors and mixed shader/mesh paths that can mask size errors.

**Architecture:** Kotlin runtime owns a single render-plan/mesh path for body, glow, head, mist, side wisp, and ribbon layers. The render-plan consumes exported preset values directly, calls the shared Kotlin port of TS layout formulas, and applies only world transforms from projectile location/facing. Any future shader path must be generated from the same render-plan and must not introduce independent geometry or scale constants.

**Truth Sources:**
- TS layout formulas: `tools/projectile-vfx-preview/src/render/projectileVfxLayout.ts`
- TS overlay semantics: `tools/projectile-vfx-preview/src/render/previewOverlayRenderer.ts`
- Runtime layout port: `src/main/kotlin/cn/kasuminova/astd/renderer/projectile/runtime/ASTDProjectileVfxLayout.kt`

## Hard Constraints

- Runtime geometry must not contain screenshot-fit constants such as `PREVIEW_*_SCALE`, `BODY_X_SCALE`, `VERTICAL_SCALE`, `looksRight`, `magicScale`, or `tune`.
- Runtime meshes must not carry generic `xScale` / `yScale` fields. Local positions are already the render contract; the manager may only rotate and translate them into world space.
- Runtime must not keep parallel shader and mesh geometry paths for the same layer. A shader may be introduced later only as a backend for the same explicit render-plan data.
- Preset parameters must not be reinterpreted in layer renderers. For example, `startWidth` may only flow through `ASTDProjectileVfxLayout.widthBase`.
- Screenshot parity checks are final visual regression checks. They are not an acceptable source for adding geometry, color, alpha, or blur constants.
- If Canvas API behavior cannot be represented exactly in OpenGL, add a named adapter with a TS API reference and focused tests. Do not hide the compensation inside layer-specific constants.

## Required Tests

- Layout parity tests for body polygon, head vertices/fill, glow line widths, side wisp paths, and ribbon wave sampling against TS-known values.
- Source guard tests that fail if runtime reintroduces hidden scale or mixed shader/mesh geometry paths.
- Runtime manager tests proving local mesh vertices are only rotated and translated, with no scale.
- Layer tests proving body/head/glow/ribbon meshes consume `ASTDProjectileVfxLayout.widthBase` directly.
- Screenshot automation remains useful only after formula parity tests pass.

## Cleanup Tasks

1. Add source guard tests for forbidden constants and shader/mesh dual-path fields.
2. Remove `ASTDProjectileVfxShaderRenderer` and all `shaderQuad` references from runtime meshes.
3. Remove `xScale` and `yScale` from `ASTDProjectileVfxBodyRenderer.Mesh` and from `ASTDProjectileVfxBodyRenderManager`.
4. Update body/head/glow renderers to use `ASTDProjectileVfxLayout.widthBase(baseLayer)` directly.
5. Update ribbon renderer to remove its local `xScale` multiplier and keep ribbon as a decoration sized from `baseTrailStartWidth * thickness`.
6. Update tests so they assert TS layout-derived values rather than hidden runtime scale values.
7. Run targeted projectile renderer tests before broader Gradle tests.

## Follow-Up Shader Rule

When shader rendering is reintroduced, the shader input must be a typed render-plan generated by Kotlin layout parity code. The shader is allowed to approximate Canvas blur/bloom, but it must not own body/head/glow dimensions, independent gradient stops, or extra scale factors.
