# ASTD 美术工作包与交付规范

> 用途：把前面的设定分析整理为可分发的工作包与统一验收口径，方便策划、原画、Sprite、武器贴图与 UI 协作。

## 1. 交付目标

本文件服务于两件事：

- 按资产类别拆分稳定的工作包
- 为不同工种提供统一的交付格式与验收口径

目标是让 ASTD 的舰船、武器贴图与 UI 资源始终共享同一套阵营识别体系。

## 3. 按工种分发建议

## 3.1 原画 / 设定
- 负责舰船结构图、风格母版、关键武器设定页与变体方案
- 输出中应包含主要功能模块、材质划分与发光层说明

## 3.2 Sprite / 舰船贴图
- 负责舰船顶视图贴图、发光蒙版说明与可拆分部件命名
- 重点保证远景轮廓、中景模块与小尺寸读感

## 3.3 武器贴图
- 负责图标、底座、枪身、发射器与镜组贴图
- 重点保证线路归属、型号差异与系列家族感

## 3.4 UI
- 负责词缀图标、Threat Tier 边框、Intel 底纹、通讯框与协议界面
- 重点保证小尺寸可读性与统一的层级结构

---

## 4. 交付格式建议

## 4.1 原画 / 设定
- PNG / PSD
- 建议包含线稿层、平涂层、发光标注层与结构注释

## 4.2 Sprite
- 保留源文件与导出图
- 建议提供标准版、发光蒙版说明与可拆分部件命名

## 4.3 武器贴图
- 提供图标、base、gun 与附属贴图的命名方案
- 同系列武器建议共享命名规则与分层结构

## 4.4 UI
- 图标与边框建议同时提供原尺寸稿与 64 / 32 / 16 像素可读性测试
- 通讯框与底板建议附带文本安全区说明

## 5. 验收口径

每项资产验收时，至少确认：

### 视觉一致性
- [ ] 是否符合 ASTD 总体风格
- [ ] 是否符合所属技术路线
- [ ] 是否与现有资产保持统一家族感

### 功能可读性
- [ ] 是否能从轮廓读出舰种、武器类别或 UI 层级
- [ ] 是否能从结构与发光读出核心功能模块
- [ ] 是否能在实际战斗缩放或小尺寸界面下保持辨识度

### 叙事匹配
- [ ] 是否传达了该资产的背景设定与战术职责
- [ ] 是否体现其危险来源与阵营气质

### 技术兼容
- [ ] 是否适合顶视图 Sprite 或装配界面显示
- [ ] 是否具备稳定的命名与分层结构
- [ ] 是否不会因过亮、过杂而破坏战斗与界面可读性

---

## 6. 协作流程

1. 先用 `00-总览与风格圣经.md` 对齐总风格
2. 舰船按 `10-舰船美术需求.md` 确认轮廓、模块与涂装
3. 武器按 `20-武器与特效需求.md` 确认系列贴图语言与图标结构
4. UI 按 `30-剧情场景与界面需求.md` 统一边框、词缀、Intel 与协议界面
5. 最终按本文件核对工作包边界、交付格式与验收口径
