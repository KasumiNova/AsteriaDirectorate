# 赏金词缀（Affix HullMod）设计稿（机制向，暂不实现）

> 本文件只做设计与命名约定，**不落到代码**。
> 目标：难度主要来自“机制放大 + 词缀组合改变决策”，数值提升只做小幅辅助。

---

## 统一约定

### 强度参数
- $k \in [0,1]$：由总缩放 $T\in[1,15]$ 归一化得到（见 `docs/story/MECHANICS.md`）。
- Tier：1/2/3（必要时可扩展到 4，但建议谨慎）。

### 词缀显示方式
- 对玩家可见：在 Intel/任务描述里用“编队特性/异常协议”方式提示，不直接暴露公式。
- 对战斗中可感知：
  - 必须有**明显的 telegraph**（音效/光效/计时器/弹道特征/编队行为变化）。
  - 必须有**可对抗的窗口**（位置、时机、目标优先级等）。

### 词缀组合原则
- 同一场战斗最多 1 个“规则改写型（R）”+ 2 个“机制放大型（M）”+ 若干“数值微调型（S）”。
- 避免“只增痛苦不增选择”的组合，例如：超强护盾 + 超强机动 + 超强 ECM 同时拉满。

---

## 词缀清单（建议优先级：R > M > S）

下面每条都给出：
- **ID（计划）**：未来若实现，建议使用的 `astd_affix_*` 命名
- **Tier**：1/2/3
- **类型**：R 规则改写 / M 机制放大 / S 数值微调
- **机制描述**：玩家可读的表述
- **强度随 k**：如何随 $k$ 放大
- **对抗方式**：玩家应该怎么打

---

## R：规则改写型（战场会“变味”）

### 1) 逻辑门槛（Logic Gate）
- **ID**：`astd_affix_logic_gate`
- **Tier**：3
- **类型**：R
- **机制描述**：目标编队在战斗中会周期性生成“假目标/错位锁定”，导弹与长距锁定会被误导。
- **强度随 k**：假目标刷新频率↑；错位持续时间↑。
- **对抗方式**：中近距确认 + 侧翼切入；优先击毁“门槛节点舰”（带特殊传感阵列的舰）。

### 2) 因果延迟（Causality Lag）
- **ID**：`astd_affix_causality_lag`
- **Tier**：3
- **类型**：R
- **机制描述**：目标编队的关键系统在“被你观察到”的那一刻往往已完成半个周期；你以为抓到了窗口，其实是上一拍。
- **强度随 k**：系统预热提示更短；反制窗口更窄。
- **对抗方式**：以“切断协同”而非单点爆发为主；对其旗舰/中继舰做持续压制。

### 3) 退场否决（No Retreat Directive）
- **ID**：`astd_affix_no_retreat`
- **Tier**：2
- **类型**：R
- **机制描述**：目标舰不会撤退；且会优先追击“试图脱离交战”的单位（不追得远，但会强制拉回战斗）。
- **强度随 k**：追击阈值更严格；短时加速更频繁。
- **对抗方式**：利用其“不撤退”反而更容易围杀；诱使其旗舰孤立。

### 4) 重构裁决（Reconstruction Verdict）
- **ID**：`astd_affix_reconstruction_verdict`
- **Tier**：3
- **类型**：R
- **机制描述**：当一艘敌舰被击毁时，会触发一次“自修复回滚”：在短时间内强化邻近舰的装甲/护盾，但同时也会造成短暂的操控迟滞。
- **强度随 k**：强化幅度↑；迟滞时间略↑。
- **对抗方式**：控制击杀节奏；选择“同一片区域连续击杀”或“分散击杀”会产生不同难度。

## M：机制放大型（让某种玩法被放大）

### 5) 协同中继（Coherent Link）
- **ID**：`astd_affix_coherent_link`
- **Tier**：2
- **类型**：M
- **机制描述**：目标编队会围绕一艘“中继舰”形成协同：护盾轮换、集火切换更快、撤退更少。
- **强度随 k**：协同半径↑；切换速度↑。
- **对抗方式**：点杀中继舰/瘫痪其引擎；利用 EMP/反护盾武器打断轮换。

### 6) 过驱窗口（Overdrive Window）
- **ID**：`astd_affix_overdrive_window`
- **Tier**：2
- **类型**：M
- **机制描述**：弧光系单位会周期性进入“过驱窗口”，爆发极强但伴随短暂热债与护盾空窗。
- **强度随 k**：爆发更强；空窗略缩短。
- **对抗方式**：熬过窗口再反打；用机动迫使其在错误距离开窗。

### 7) 透镜折射（Lens Refraction）
- **ID**：`astd_affix_lens_refraction`
- **Tier**：2
- **类型**：M
- **机制描述**：透镜系单位对“直线弹道/导弹齐射”有明显反制倾向（偏折/诱饵/干扰）。
- **强度随 k**：诱饵数量↑；干扰强度↑。
- **对抗方式**：分批次齐射；用主炮压迫替代导弹一波流。

### 8) 相位债务（Phase Debt）
- **ID**：`astd_affix_phase_debt`
- **Tier**：3
- **类型**：M
- **机制描述**：相位舰在长时间相位后会出现“债务结算”：短暂无法相位/或相位维持代价暴涨。
- **强度随 k**：结算更频繁；惩罚更重。
- **对抗方式**：逼迫其长相位；在结算瞬间完成包夹。

### 9) 诱饵蜂群（Decoy Swarm）
- **ID**：`astd_affix_decoy_swarm`
- **Tier**：1
- **类型**：M
- **机制描述**：目标编队会释放大量低威胁诱饵单位（不一定造成伤害，但会占锁定/遮挡弹道）。
- **强度随 k**：诱饵存续时间↑。
- **对抗方式**：使用范围火力/点防清场；不把主火力浪费在诱饵上。

### 10) 反应堆回灌（Reactor Backfeed）
- **ID**：`astd_affix_reactor_backfeed`
- **Tier**：2
- **类型**：M
- **机制描述**：当敌舰过载时，会向附近友军“回灌”一定幅能（让其短时更敢打），但过载舰自身会受到额外结构压力。
- **强度随 k**：回灌量↑。
- **对抗方式**：制造“孤立过载”而非群体过载；在回灌峰值后反打。

## S：数值微调型（只做口味，不做主菜）

### 11) 超频线圈（Overclocked Coils）
- **ID**：`astd_affix_overclocked_coils`
- **Tier**：1
- **类型**：S
- **机制描述**：能量武器节奏更快，但热债更重。
- **强度随 k**：射速增益与代价随 $k$ 上升。
- **对抗方式**：拉扯耗散；逼其在高幅能区间开火。

### 12) 干扰节点（Jamming Nodes）
- **ID**：`astd_affix_jamming_nodes`
- **Tier**：1
- **类型**：S
- **机制描述**：机动更强、自动火控更稳。
- **强度随 k**：机动/命中增益随 $k$ 上升。
- **对抗方式**：点防与近距压制；利用地形遮挡减少其稳定输出。

### 13) 熵化护盾（Entropy Shields）
- **ID**：`astd_affix_entropy_shields`
- **Tier**：2
- **类型**：S
- **机制描述**：护盾更硬但维持更贵。
- **强度随 k**：减伤与代价随 $k$ 上升。
- **对抗方式**：拖入持久战；利用其维持成本迫使其降盾。

## 额外：支线专属词缀（故事碎片味道）

> 仅用于“唯一支线任务”，让支线更像“异常遭遇”而不是主线复刻。

### 14) 录音回放（Recorded Loop）
- **ID**：`astd_affix_recorded_loop`
- **Tier**：2
- **类型**：M
- **机制描述**：敌舰会周期性重复一次短机动序列（像录像回放）。
- **强度随 k**：回放更频繁。
- **对抗方式**：观察规律后预判拦截点。

### 15) 断章（Fragmented Orders）
- **ID**：`astd_affix_fragmented_orders`
- **Tier**：1
- **类型**：M
- **机制描述**：敌编队在战斗中会出现“短暂失协同”与“突然集火”交替。
- **强度随 k**：交替幅度更大。
- **对抗方式**：利用其失协同期切断阵型。

## R：更多规则改写型（高阶、慎用）

### 16) 战区封闭（Lockdown Zone）
- **ID**：`astd_affix_lockdown_zone`
- **Tier**：3
- **类型**：R
- **机制描述**：战斗开始后一段时间内，战区边界会被“封闭”——靠近边界的舰船会遭遇短暂的操控迟滞/传感器失真（模拟“测试区不可退出”）。
- **强度随 k**：封闭持续更久；迟滞更明显。
- **对抗方式**：避免被压到边线；让敌方在边线附近被集火。

### 17) 目标涂抹（Target Smear）
- **ID**：`astd_affix_target_smear`
- **Tier**：2
- **类型**：R
- **机制描述**：锁定目标的“位置”会在短时间内被涂抹成一个范围，导致远程狙击更难命中，但近距压制更稳定。
- **强度随 k**：涂抹半径↑。
- **对抗方式**：缩短交战距离；用面杀/扫射替代单发狙击。

---

## M：更多机制放大型（建议主力池）

### 18) 分布式栅格护盾（Distributed Grid）
- **ID**：`astd_affix_distributed_grid`
- **Tier**：2
- **类型**：M
- **机制描述**：目标编队会表现出“护盾栅格化”：某些舰在短时间内承担更多护盾压力，随后快速轮换。
- **强度随 k**：轮换更快；轮换半径更大。
- **对抗方式**：盯住“轮换节点舰”持续压制；用 EMP/离子武器打断轮换节奏。

### 19) 熱交换协议（Thermodynamic Exchange）
- **ID**：`astd_affix_thermodynamic_exchange`
- **Tier**：2
- **类型**：M
- **机制描述**：敌舰在通风/过载期间会向附近友军转移一部分热债（让队形更“敢打”）。
- **强度随 k**：转移更频繁。
- **对抗方式**：拉开队形让其无法互相“分摊”；点杀分摊源头。

### 20) 引力脉冲（Gravity Pulse）
- **ID**：`astd_affix_gravity_pulse`
- **Tier**：2
- **类型**：M
- **机制描述**：透镜系单位会周期性释放引力脉冲：短暂改变附近弹道/速度，打乱齐射节奏。
- **强度随 k**：脉冲半径↑；频率↑。
- **对抗方式**：错峰齐射；保持侧向速度避免被“拉直”。

### 21) 再部署脉冲（Reinforcement Ping）
- **ID**：`astd_affix_reinforcement_ping`
- **Tier**：3
- **类型**：M
- **机制描述**：当敌方旗舰结构降至阈值时，会触发一次“再部署脉冲”：刷出一批同化护卫/无人僚机（数量有限）。
- **强度随 k**：增援数量↑；触发阈值更早。
- **对抗方式**：不要把旗舰压到阈值后又“收手”；提前清理机动位，避免增援包夹。

### 22) 载荷拒止（Payload Denial）
- **ID**：`astd_affix_payload_denial`
- **Tier**：2
- **类型**：M
- **机制描述**：敌舰会优先拦截导弹/鱼雷，且会在关键时刻集中点防（表现为“导弹一波流更难奏效”）。
- **强度随 k**：点防集中更频繁。
- **对抗方式**：分批次诱饵导弹；用能量/弹道压制打开点防缺口。

## S：补齐当前已存在的数值型词缀（用于调味）

### 23) 超压推进（Reckless Drive）
- **ID**：`astd_affix_reckless_drive`
- **Tier**：2
- **类型**：S
- **机制描述**：更快更凶，但更怕被抓住（装甲更脆）。
- **强度随 k**：机动增益↑；代价↑。
- **对抗方式**：用控场迫使其“冲过头”；在其暴露装甲面时集火。

### 24) 相位不稳定（Phase Instability）
- **ID**：`astd_affix_phase_instability`
- **Tier**：3
- **类型**：S/M（偏机制）
- **机制描述**：相位维持代价提高，迫使相位舰必须“结算”；同时常规火力略强。
- **强度随 k**：结算更痛。
- **对抗方式**：逼其长相位→等结算；或用持续压制让其无法安心结算。

### 25) 零余量纪律（Zero Margin）
- **ID**：`astd_affix_zero_margin`
- **Tier**：3
- **类型**：S
- **机制描述**：更省幅能/更强压制，但峰值更短、CR 损耗更快。
- **强度随 k**：压制更强；峰值更短。
- **对抗方式**：拉长战斗节奏；逼其在低 CR 阶段继续交战。

## Omega 向词缀（仅用于 10% Omega 池或终局遭遇）

### 26) 分形碎片（Fractal Shards）
- **ID**：`astd_affix_fractal_shards`
- **Tier**：3
- **类型**：M
- **机制描述**：敌舰被击毁时会释放少量“分形碎片”无人机，短时间内干扰锁定并补刀。
- **强度随 k**：碎片数量↑；存续时间↑。
- **对抗方式**：点防清场；选择击杀顺序避免连续触发。

### 27) 向量静默（Vector Silence）
- **ID**：`astd_affix_vector_silence`
- **Tier**：3
- **类型**：R
- **机制描述**：短时抑制战场信息：雷达更新变慢、战术 UI 提示减少（以“测试区信息不对称”表现）。
- **强度随 k**：静默持续更久。
- **对抗方式**：依赖编队站位与视距；提前设定战术指令。

### 28) 现实筛网（Reality Sieve）
- **ID**：`astd_affix_reality_sieve`
- **Tier**：3
- **类型**：R
- **机制描述**：战场局部出现“时间流偏差”，投射物与机动节奏会产生错拍（轻度版即可，不要太晕）。
- **强度随 k**：偏差更明显。
- **对抗方式**：减少依赖单次爆发；用持续火力与包夹保证命中。

## 叙事型词缀（只在特定主线节点出现）

### 29) 双重校验（Dual Validation）
- **ID**：`astd_affix_dual_validation`
- **Tier**：3
- **类型**：R
- **机制描述**：编队会在战斗中执行两段式验证：第一段偏火力压制，第二段偏干扰封锁；两段之间会有短暂“校验停顿”。
- **强度随 k**：两段更极端；停顿更短。
- **对抗方式**：在校验停顿时反打；提前准备反干扰/反爆发手段。

### 30) 审判预热（Verdict Warm-up）
- **ID**：`astd_affix_verdict_warmup`
- **Tier**：3
- **类型**：M
- **机制描述**：战场会先出现“锚点节点”，摧毁锚点后才会进入真正的 Boss 交战阶段。
- **强度随 k**：锚点更难处理。
- **对抗方式**：分工：一部分清锚点，一部分拦截刷新的护卫。

## 备注：实现建议（以后再做）

- “规则改写型（R）”大多无法靠纯 HullMod 完成，通常需要：
  - 给旗舰/中继舰挂隐藏 HullMod + 战斗侧插件（CombatPlugin）
  - 或给整支舰队挂一个战役侧脚本，在进入战斗时注入临时战斗脚本
- 建议先实现 2~3 个 R 型词缀（如 逻辑门槛/因果延迟/退场否决），就能显著提升赏金体验的辨识度。
