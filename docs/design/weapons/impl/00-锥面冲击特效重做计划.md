## 1. 动机与观感评审结论

现有实现（`ConeImpactVfx` / `ConeImpactVfxComponent`）：顶点两口 vanilla 闪光粒子 + N 条 BoxUtil 渐变拖尾射线按等角距排成扇面，smoothstep 包络推长，心跳保活、定时器淡出。实机截图与 AOD-7 开火特效（`Aod7OnFireEffect`：双椭圆环 + DistortionEntity + 6 颗 nebula 烟雾 + halo）并排对比后定论，离散射线扇面有五条病灶：

1. **机械量化感**：N 条射线等角距、等宽、等长、同亮同灭，读感是"孔雀开屏"而非一次冲击。
2. **读感错位**：硬边平行光刺像"持续激光束"，不是"一闪而过的冲击波前"。
3. **色温割裂**：顶点橙白火球（暖）与扇面冷蓝不统一。
4. **空间脱节**：射线出发点与顶点火球各画各的，不像同一个爆炸体。
5. **覆盖空洞**：射线间大空隙，读不出连续锥形 AoE 覆盖边界。

AOD-7 式的优点：火球 + 烟雾 + 扩张环是连续体，烟雾给体积感，椭圆环给方向性与扩张动感，色系统一，软衰减。其短板是纯烟雾 + 环的锥角朝向/覆盖边界读感弱——而射线扇面的唯一优点恰是**显式画出锥角覆盖**（本仓库机制可视化铁律：机制范围必须玩家可读）。

**已定方案方向（用户已认可）**：保留方向性、换掉离散射线——锥面主体改连续扇形楔块（渐变贴图 + 软边），叠 UV 滚动/抖动破均匀；叠 aod7 式扩张弧表达"波前在推进"；顶点烟雾补体积感；全套冷蓝色温统一；各层错开几十毫秒起止，破同帧同灭。

## 2. 渲染可行性与选型

### 2.1 楔块主体：三候选评估

**(a) BoxUtil TrailEntity 单条超宽拖尾压扁成扇形 —— 否决。** TrailEntity 的几何拓扑是"沿节点折线的等宽/锥形条带"：两节点 + 大宽度只能得到矩形板，得不到径向张开的扇形；用多节点弧线排布得到的是弧带而非填充扇面；要填满扇面只能同心叠多条弧带——那是把"离散射线"换成"离散环"，病灶原样保留。且 fill/宽度渐变的 shader 语义全部按条带假设设计，强扭即兜底代码。

**(b) OglEllipseRingRenderer 画扇形弧带 —— 否决（对楔块主体）；采用（对扩张弧层）。** 该渲染器画的是纯线框（`GL_LINE_LOOP`、additive、无贴图无填充），画不出连续面状楔块。但它正是"扩张弧"层的正确工具：aod7 已量产验证（32/16 双环、0.22s、280 扩速、72 段），自管理生命周期，无需树推进。

**(c) 自建扇形三角网格 + 既有 TexTrailRenderer —— 采用。** P2 收口的 `TexTrailRenderer` 管线能力完全覆盖需求：CPU 世界系顶点流（8 浮点交错 x,y,u,v,r,g,b,a）、支持 `GL_TRIANGLES` 原始三角形模式、贴图自管缓存（带长向 REPEAT 可滚动、横向 CLAMP）、真 bloom 合成（弹头网格已走同管线）。楔块只需一个新纯函数生成极坐标网格顶点流 + 一个新 Component 持 handle 逐帧推送，零新 GL 代码。仓库内已有同款纯函数先例（`texTrailStrip` / `texTrailMeshTriangles`）。

**选型结论：楔块主体走 (c)，扩张弧走 (b)（弧段扩展后），烟雾/闪光走 vanilla 粒子。**

层位说明：`TexTrailRenderer.Plugin` 固定绘制于 `ABOVE_PARTICLES_LOWER`（texTrail 管线契约，保证"拖尾垫底、弹头盖上"），层内按 renderOrder 排序。楔块进入该管线即固定此层，renderOrder 定为 350/351（压在弹体拖尾基线 361 之下，保证「扇面在底」）；环固定 `ABOVE_SHIPS_AND_MISSILES_LAYER`（渲染器现状）；闪光为 vanilla 粒子。三者均在舰船之上，构图次序（楔块垫底 → 环 → 闪光粒子）符合"扇面在底、波前与闪光盖上"的读感，目检确认即可。原 `ConeImpactVfxSpec.layer` 字段因此失去承载对象，随本次删除（见 §5）。

### 2.2 贴图素材（复用，零新素材）

`contents/graphics/fx/` 候选贴图 alpha 带实测（X=横向 CLAMP、Y=带长向 REPEAT；形在 alpha 通道）：

| 贴图 | 尺寸 | alpha 带横向范围（实测中位） | 图案特征 |
|---|---|---|---|
| `astd_trails_contrail.png` | 64×128 | X ∈ [0.20, 0.78] | 宽云状噪声带，边缘絮状软衰减 |
| `astd_trails_surge.png` | 64×256 | X ∈ [0.12, 0.95] | 近全宽混乱条纹，高能量湍流感 |
| `astd_trails_smooth.png` | 64×256 | X ∈ [0.50, 0.89] | 干净宽软带，但明显偏单侧 |
| `gr_trails_lightning.png`（已随 gr_ 前缀清理删除） | 64×128 | 分散碎纹 | 闪电碎纹，过碎不衬大扇面 |

UV 映射约定（顶点流生成侧负责，片元着色器语义为 `tex.x = v*0.5+0.5`、`tex.y = u`）：
- **u（径向）**= r / tileLength − scroll，tileLength 默认 = 锥长（一张贴图铺满径向），scroll 随时间推进 → 花纹沿径向向锥缘爬行（MagicTrail textScroll 手法）。
- **v（角向）**：θ ∈ [−halfAngle, +halfAngle] 线性映射进贴图 alpha 带（带外 alpha≈0 → 扇缘自然软边）。映射带常量与贴图配对：contrail 用 [−0.60, +0.56]（= 2×[0.20, 0.78]−1），surge 用 [−0.76, +0.90]（实施落位：两组常量放根组件 `ConeImpactVfxComponent` companion）。

**选型**：
- **楔块底层（填充/体积）= `astd_trails_contrail`**：云状噪声提供湍流体积感，正中病灶 1（破均匀），带宽居中对称。
- **楔块图案层（能量/动感）= `astd_trails_surge`**：近全宽混乱条纹，滚动更快、alpha 更低，叠在底层之上（MagicTrail 多层错参手法）。
- `astd_trails_smooth` 偏单侧、`lightning` 过碎，均不采用。

### 2.3 扩张弧（OglEllipseRingRenderer 弧段扩展）

现状 `RingSpec` 只能画全椭圆线环（aod7 参数：aSideHalf=32、bAlongHalf=16、duration=0.22、expandSpeed=280、segments=72、lineWidthPx=1.35）。锥面要的是"朝前的弧"（波前截面），需扩展两个参数（参数角制，与渲染器内部 `ang = phase + step*i` 直接对应）：

- `arcCenterDeg: Float = 90f`：弧心参数角（90° = 椭圆朝 +facing 最前点）。
- `arcSweepDeg: Float = 360f`：扫掠角；≥360 走原 `GL_LINE_LOOP` 全环（**aod7 两处既有调用零行为变化**），<360 走 `GL_LINE_STRIP` 画 [center−sweep/2, center+sweep/2] 弧段。
- 弧段模式下随机相位归零（实施补充）：随机相位会把弧甩离朝向，仅全环模式保留随机相位。

### 2.4 烟雾（vanilla 粒子）

aod7 用 `engine.addNebulaParticle(p, v, radius, 1.3f, 0.08f, 0.22f, 0.7f, smoke, true)` × 6（背向散布）。锥面版方向反过来：沿锥向锥内喷出，补顶点体积感并衔接扇面起点（病灶 4）。自管理生命周期，无需树推进。

## 3. 目标视觉分层设计

| 层 | 几何 | 材质/颜色 | 时序 | 职责 |
|---|---|---|---|---|
| **顶点闪光** | 2 颗 vanilla 粒子（addSmoothParticle，尺寸 = length×0.30 clamp [30,220]） | flashColor（内）+ coreColor（核），与扇面同族冷色 | t=0，0.12~0.18s 一闪即走 | 起爆点锚定 |
| **顶点烟雾** | 2 批 10 颗 nebula：批 1（t=0，6 颗）顶点 10su 圆内；批 2（t=+0.06，4 颗）轴上 0.3L 附近。方向 = facing ± halfAngle×0.8 随机，速度 = length×0.35 ±40%，半径 = clamp(length×0.05, 12, 36)，endSizeMult 1.4，存续 0.7s | fringeColor α70（aod7 同式），additive | t=0 / t=+0.06 | 体积感、衔接顶点与扇面 |
| **楔块底层** | 极坐标三角扇：径向 6 段 × 角向 A 段（A=clamp(ceil(全角/5°), 8, 36)，贯星 80° 全角 → A=16，破晓 80° 半角 → A=32），2×6×A 三角形；角向每列固定抖动 ±2°（spawn 时随机一次，生命周期不变——MagicTrail dispersion 的静化版，破等角距） | `astd_trails_contrail`，RGB = coreColor；u 滚动 300 su/s | expand 0.14s（smoothstep）→ hold → fadeOut 0.22s | 连续锥面主体，扇缘恒对齐 ±halfAngle（机制可视化铁律） |
| **楔块图案层** | 同上网格（同一顶点流函数，独立 handle，renderOrder 其上） | `astd_trails_surge`，RGB = fringeColor，整体 alpha ×0.5；u 滚动 510 su/s（底层 ×1.7） | 同底层包络 | 能量湍流、破均匀 |
| **扩张弧 ×3** | 轴上 0.35L / 0.7L / 1.0L 处椭圆弧：aSide = 位置×tan(halfAngle)×0.9，bAlong = aSide×0.5，sweep 140° 朝前，segments 48 | fringeColor α130/100/70，lineWidth 1.3/1.15/1.05 | t=+0.03/+0.08/+0.13，duration 0.20/0.18/0.16，expandSpeed 240/300/360 | "波前在推进"的接力读感 |

**径向包络（楔块顶点 alpha）**：frontR = length × smoothstep(t/expand)；alpha(r) = 全局包络 × (BASE 0.35 + PEAK 0.65 × 三角峰((frontR−r)/(0.3×length)))；**r > frontR 的未抵达区保留 BASE×0.3 淡影**——展开期扇形边界（±halfAngle 全貌）恒隐约可见，机制覆盖范围从第一帧可读；亮带从顶点推到锥缘给出冲击波前动感。fadeOut 段全局包络线性归零。

**全局包络**：expand 段 0→1（smoothstep，沿用现公式）→ hold 段恒 1（至 duration − fadeOut）→ fadeOut 段线性 1→0。

**时序错开总表**（组件常量，目检面）：t=0 闪光 + 烟雾批 1 + 楔块 attach；t=+0.03 弧 1；t=+0.06 烟雾批 2；t=+0.08 弧 2；t=+0.13 弧 3。楔块 fadeOut 在 duration−fadeOut 启动。各层起止均不同帧，病灶 1 的"同亮同灭"解除。

**调色统一**：三调用方现行调色板（贯星冷蓝白 core(185,220,255)/fringe(95,160,255)、正电子蓝色调、穷距冷白）不动；闪光/烟雾/弧/楔块全部从 coreColor/fringeColor/flashColor 派生，不再出现独立暖色——病灶 3 由派生关系保证。

## 4. RenderEntity 树实现方案

### 4.1 树结构

```
ConeImpactVfxComponent（根，RenderEntityImpl，layer/renderOrder 沿用现状）
└── ConeWedgeComponent × 2（底层 contrail + 图案层 surge，各持一枚 TexTrailRenderer.Handle）
```

根职责（对齐现有 ConeImpactVfxComponent 的"几何常量创建期定死、每帧只读 elapsed"先例）：
- `onAttachSelf`：顶点闪光（vanilla 粒子）+ 烟雾批 1。
- `advanceSelf`：读 `ctx.frame.elapsed`，按阈值表恰好触发一次弧 1/2/3 与烟雾批 2（布尔标记位，幂等）；子节点由基类递归推进。
- `beginFadeOutSelf` / `onDetachSelf`：根自身无后端句柄；递归由 `RenderEntityImpl` final 骨架保证。

`ConeWedgeComponent` 职责：
- `onAttachSelf`：`openStream` 探测贴图可读（`TexTrailComponent` 先例）→ `TexTrailRenderer.createHandle`；失败记 WARN 返回 false（本层缺席，其余层照常——故障隔离带日志，非静默兜底）。
- `advanceSelf`：调纯函数重建顶点流，`handle.update(renderOrder, texturePath, vertices, triangles = true)`；淡出复用 `ASTDProjectileVfxLayerFadeState` 乘进全局包络。
- `beginFadeOutSelf`：`fade.begin(seconds)`。
- `onDetachSelf`：`handle.delete()`（幂等）。

### 4.2 生命周期（心跳方案变更）

- **楔块不再需要心跳**：现有心跳 0.35s 是 BoxUtil 全局定时器的保活机制；TexTrailRenderer.Handle 由组件逐帧推顶点流持有，alpha 每帧由包络算出，无定时器参与。树的 detach（OneShotVfxPlugin 到期）即删 handle。
- **弧/烟雾/闪光全部自管理**（渲染器时长 / vanilla 粒子时长），不依赖树存活。最晚收尾为烟雾批 2（0.06+0.7s），其存续与树无关。
- **OneShotVfxPlugin 驱动寿命 = spec.duration + 0.15 不变**：楔块淡出包络在 duration 内完成，余量语义同现状。

### 4.3 纯函数拆分（对齐 `layoutRayOffsets`/`texTrailStrip` 先例）

新文件 `src/main/kotlin/cn/kasuminova/astd/impl/render/ConeWedgeMesh.kt`，全部纯函数可单测：

| 函数 | 职责 |
|---|---|
| `wedgeAngularSegments(halfAngleDeg): Int` | 角向分段数：ceil(全角/5°) clamp [8, 36]（窄锥不少于 8 段保圆弧、宽锥防爆闸） |
| `wedgeEnvelope(t, expandSeconds, holdEnd, duration): Float` | 全局 alpha 包络（expand smoothstep / hold 1 / fadeOut 线性） |
| `wedgeFrontRadius(t, expandSeconds, length): Float` | 波前半径 frontR |
| `wedgeRadialAlpha(r, frontR, band): Float` | 径向 profile：BASE 0.35 + 三角峰；r > frontR 区 BASE×0.3 |
| `coneWedgeFan(origin, facingDeg, halfAngleDeg, length, radialSegs, angularSegs, vLo, vHi, tileLength, scroll, frontR, envelopeAlpha, red, green, blue, angularJitter): FloatArray` | 顶点流主函数：极坐标网格 → 世界系 8 浮点交错三角形流（布局同 `TEX_TRAIL_VERTEX_FLOATS`）；red/green/blue 为顶点染色三通道（两层楔块 coreColor/fringeColor 分染，实施时补入签名）；角向抖动表由调用方 spawn 时生成一次传入 |

`ConeImpactVfx.spawn` 保留入口校验（length/duration 非正 WARN + null；halfAngle/expand/fadeOut clamp + WARN），删 ray 布局调用，改算角向分段 + 抖动表，建树（根 + 两楔块子节点）后驱动不变。

### 5.2 调用方零改动（grep 核实）

三处 `ConeImpactVfxSpec(...)` 构造（`PiercingLanceVfx.spawnImpact`、`PositronShockwaveFuseScript`、`QiongjuePhaseRailgunOnHitEffect`）均只用 6 个命名参数（origin/facingDeg/halfAngleDeg/length/coreColor/fringeColor），不触碰被删字段；新增字段全有默认值。**三调用方源码一行不改**，`ConeImpactVfx.spawn(engine, spec)` 签名不变，遥测 bump 点（各自 `TELEMETRY_CONE_VFX`）不变。摧锋未实装，无影响。

### 5.3 命名与规范对照

- 无反射、无空 catch（贴图探测失败 WARN 带异常对象）。
- 新增类 `ConeWedgeComponent` / 纯函数文件 `ConeWedgeMesh.kt`，无 Service/Manager/Controller/Runtime 命名；`OglEllipseRingRenderer` 为参数扩展不改名。
- 无占位实现、无兼容兜底：被删字段/函数/测试一次性清干净；贴图故障为带 WARN 的分层隔离（沿用 spawnRays 既有语义），非静默降级。
- Spec 维持 data class + 命名参数默认值（Kotlin 等价 Builder，三案构造点已证实该形态够用），不另立 Builder 类。

## 6. 烟测验证方案

### 6.1 自动化证据（沿用既有相位机，零改动）

- `piercing_lance_basic` 相位机（mount → cycle → cluster → enemy-scale）不触碰；锥面 VFX 证据沿用调用方遥测键 `astd_piercing_lance_cone_vfx`（由 `PiercingLanceVfx` bump，不受内部实现替换影响），telemetry JSON 的 `plConeVfx` 字段语义不变。
- 正电子/穷距场景同理：`psConeVfx` / `qjConeVfx` 不变。
- 到达终态即退出（烟测后必关游戏）。

### 6.2 目检点位（dev 实机）

1. **连续性**：命中帧扇面无条带缝隙、无"孔雀开屏"量化感；图案滚动湍流可读。

## 10. v2 修订（2026-07-31 实机评审后定案）

### 10.1 v1 楔块方案的实机否决结论

v1（§1~9：连续扇形楔块 + 双弧 + 顶点烟雾）按 §8 全量实施并通过单测后上实机目检，用户评审否决，三条理由：

1. **弧形边界太明显**：规则扇形轮廓（即便带 ±2° 列抖动）读不出自然的随机感，冲击体不像爆炸产物。
2. **没有 AOD7 类似的多条锥状体**：单扇面 + 双弧的层数太少，缺 aod7 式多层壳体接力读感。
3. **太机械而且太亮**：几何扇面均匀发光 + texTrail bloom 管线（离屏提取 emissive 增益 + 模糊合成）把整扇过曝成白块——bloom 管线很可能就是「太亮」的根因。

**用户定案方向（原话）**：「仍然考虑在 AOD7 的锥状冲击特效上去追加星云效果」——退役楔块，锥面主体回到 `Aod7OnFireEffect` 配方（多道椭圆弧 + DistortionEntity + nebula 烟雾 + halo）的锥化变体，并追加星云烟雾补体积。

### 10.7 v2.2 弧环加粗包络 + 三角碎片替换星云（2026-07-31 实机评审三次反馈）

**用户原话两条**：

1. 「弧环你可以留，但是现在的线条太细了（至少需要 10px，加逐渐升高的透明度过渡），两侧收尾也要透明度过渡。」
2. 「飞出的小星云全部换成随机旋转的三角形碎片就够了。」

**A. 弧环加粗 + 逐顶点 alpha 包络**：

- `OglEllipseRingRenderer.RingSpec` 新增 `arcAlphaPeakPos: Float = -1f`（默认关闭，全环与弧段既有调用零行为变化）；弧段分支启用时 glColor4f 移进顶点循环，per-vertex alpha = aCol × `arcAlphaEnvelope(t, peakPos)`（internal 纯函数：[0,peak] smoothstep 渐升、[peak,1] smoothstep 渐落，两端归零，治「弧形边界太明显」的硬边收尾）。全环分支保持单次 glColor4f 不变。
- 锥面侧：ARC_LINE_WIDTHS 1.3/1.2/1.1/1.0 → **12/11/10/10**（≥10px），`arcAlphaPeakPos = 0.65`（峰值偏前，读感「沿弧逐渐升高」）。
- **glLineWidth 驱动上限说明**：固定管线宽线（平滑线）的可用最大宽度由驱动实现决定（常见上限 10px 档），超限被驱动自然 clamp 不报错；外层 2× 线圈（24/22/20px）同理必然 clamp——两层最终等宽是可接受的视觉结果（亮核 + 同源外晕），不做额外处理。aod7 两处既有调用（全环 + 未传新字段）零行为变化。

| 参数 | 取值 | 说明 |

| 形状 | 等边三角 + 两边比 0.7~1.3 随机偏斜 | 顶点坐标质心居中，自旋不偏心 |
| 边长 | clamp(length×0.03, 6, 16) ×随机(0.7~1.3) | 随锥长缩放 |

| 寿命 | 0.45~0.65s 随机 | — |

- 三批错峰触发框架、批次数（顶点 6 @t=0 / 锥内 8 @+0.05 / 锥缘 4 @+0.1）、轴向角向散布模型全部保留，只换「生成什么」；碎片组件作为子节点 attach 时挂上。
