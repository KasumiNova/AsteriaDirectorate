## 5. 冒烟与回归流程

### 5.1 单组标准烟测流程（每组武器 PR 前必跑）

1. `./gradlew :ss-csv:generateSsCsv` → 生成物核对（weapon_data.csv 行 / `.proj` 内容 / descriptions.csv 键名不泄漏）。
2. `./gradlew copyContents`（生成物叠加到 contents）→ `deployMod` 到 `mods/ASTD`。
3. `launchSmokeTestGame` 启动 automation 烟测，按本组规格「烟测检查点」逐项过检：
   - 01 §4.2（10 项）、02 §4.2（8 项）、03 §4.2（7 项）、04 §4.2（8 项）、05 §2.5 烟测（8 项）、06 §4.2（8 项）、07 §4.2（8 项）、08 §4.2（10 项）、09 §4.2（8 项）、10 §4.2（8 项）。
4. **到达终态即退出游戏，不干等超时**（用户铁律：烟测后必关游戏）；目检结论（截图/录屏/日志）留在 PR 描述。
5. devMode FPS 监控：本组规格登记的每帧成本项（BuffTickPlugin、涡旋 300su、锥面 600su、连跳峰值、多发齐射 AI）无明显掉帧。

### 5.2 回归口径

- **基建回归**：第 0 波每个 PR 合入前跑基建单测全集（00 §1.4 七条 + §2.4 五条）+ 既有测试全绿；Buff API 合入后 01/04/05 三组任选一组冒烟做首批落地回归。
- **波次回归**：第 1 波全部合入后跑一次全武器装配烟测（dev 仓储取全部量产件 + 控制台取稀有件），确认共享文件收口后无键名泄漏、无 VFX 路由错位、number 无撞号。
- **最终回归**：第 2 波收口后跑全量单测 + 十组装配/开火综合烟测一场，逐项核对 §3 矩阵；确认弹体 VFX 已退役 JSON 映射无依赖、共享调色板沉淀、strings.json 协议补行三项收口动作同步完成。

### 5.3 烟测通用检查点（每组都过，组规格不再重复）

- dev 仓储投放正确（量产件蓝图可学习可装配；稀有件 `no_drop` 不进掉落/codex）。
- 装配界面名称/tip/角色/desc 全中文、无键名泄漏、弯引号渲染正常（05/07 重点）。
- 机制反馈铁律：本组所有特殊数值机制（叠层/增伤/EMP/射程/同步）各有 HUD/特效/浮字通道，缺一项视为未完工。

- 日志：无 NPE/异常；规格登记的 WARN/INFO 防线各按其触发条件出现恰好一次。
